# Infrastructure as code

Check identity and IAM scope, public network exposure, trust relationships, workload identity, secret and state
handling, encryption, Kubernetes RBAC and security contexts, isolation boundaries, destructive lifecycle changes, and
defaults that make a resource reachable or privileged in production.

A finding must trace a changed declaration to a concrete access, exposure, persistence, or availability consequence. Do
not report generic cloud or Kubernetes hardening advice without a reachable security impact.
