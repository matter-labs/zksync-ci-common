# Protocol state transitions

Check transition validity, canonical ordering and encoding, replay protection, state-root and commitment binding, batch
and block boundaries, reorg and finality assumptions, data-availability dependencies, upgrade compatibility, resource
accounting, and deterministic behavior across implementations.

A finding must show an invalid transition being accepted, a valid transition being rejected, or honest participants
deriving incompatible state. Do not report unspecified protocol behavior without an exploitable invariant violation.
